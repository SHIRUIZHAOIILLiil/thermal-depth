# SD2.1 TADP-style direct depth: frame caption versus empty caption

Independent experiment. No old experiment files or checkpoints are modified.
This is a thermal/sparse-LiDAR adaptation, NOT a reproduction of TADP's RGB NYUv2 results.
No teacher, pseudo-depth, test-set access, depth-VAE target, or Lotus task switcher.

## Frozen recipe

- Original SD2.1-base from the existing audited `Manojb/stable-diffusion-2-1-base`
  Hugging Face cache. Offline only. U-Net SHA256 must equal
  `6dfae3e5f7d459b50f4b0850ead945972c75bb0e1897628933e169eb43974214`.
  The smoke freezes all component/config/tokenizer file hashes and snapshot path.
- Freeze the matching VAE encoder and 1024-wide text encoder; full U-Net training.
  Original four-channel input. No caption-trained thermal checkpoint initialization.
- `uint16` left thermal -> shared percentile conversion -> replicate 3 channels ->
  [-1,1]. Native 256x640, no resize/crop/flip/jitter and no ImageNet normalization.
- VAE posterior mode times its scaling factor; fixed timestep 1; no added noise,
  CFG, sampling loop, reconstruction task, or final denoising projection.
- Four TADP-equivalent feature taps: Diffusers up0 resnet1, up1 attention1,
  up2 attention1, up3 attention2. These correspond to LDM output blocks 1/4/7/11,
  not simply all whole up-block outputs. Reverse to fine-to-coarse before the head.
- TADP-style aggregation (1536 channels), three deconvolutions (32 channels),
  192-channel convolution, two bilinear x2 upsamplings, depth convolutions,
  FP32 `80*sigmoid(logits)` in metres. New layers randomized identically in both arms.
  No optional text adapter, alpha gate, attention-map concatenation or DA2 module.
- Frame captions from existing manifests, or tokenizer-produced empty strings.
  Both use 77 positions and native SD2 CLIP causal attention, without an explicit
  padding mask in CLIP/U-Net. Empty is not an all-zero embedding. The two arms
  have identical initial PARAMETERS, not necessarily identical initial predictions.
- Official eight train sequences / 75,688 frames; three validation sequences /
  14,249 frames. Existing thermal-view /thr/ GT checks and file hashes apply.
- GT PNG / 256 gives metres. SiLog lambda .5, pooled valid pixels per microbatch,
  `finite(gt) & gt>.001 & gt<80`; FP32 loss; no alignment during training.
- Seed 43, batch 4, accumulation 3, 20,000 optimizer updates (240,000 image visits,
  about 3.17 dataset passes). No resource/quality rejection at 8k.
- AdamW betas .9/.999; peak U-Net lr 5e-6, new head lr 5e-4; weight decay .1
  except bias/1-D normalization parameters. 500-update linear warmup (nonzero
  first lr), then polynomial .9 decay to zero. Clip norm 1. BF16 train, FP32
  VAE/text/loss, U-Net gradient checkpointing. This schedule is our adaptation.
- Exact consumed-image cursor, optimizer, scheduler, Python/NumPy/Torch/CUDA RNG
  restored on resume; DataLoader prefetch never defines the resume cursor.

## Why sparse GT is possible

The old Lotus-D branch still predicts a VAE-encoded depth target. Filling absent
depth with zero and masking after encoding does not undo spatial mixing inside
the VAE. This motivated completion in our previous pipeline, not a theorem that
all Iris-like models require dense GT.

Here GT is never encoded: predictions are directly indexed at valid LiDAR pixels
for loss. Invalid positions have no direct target gradient. The model still outputs
a dense map, but accuracy where LiDAR is missing is NOT established by sparse
evaluation. Original TADP's published depth experiment is on NYUv2; this sparse
thermal adaptation itself remains an experiment, not a published guarantee.

## Validation, not final-paper unified evaluation

Reuse `ms2_eval.official_protocol.evaluate_sample`: Bridge official valid range
(.001,80), ssi and none, per-frame macro metrics. This is the current DA2-comparable
validation protocol, not the separate unified-v1 protocol with a .1 m lower bound.
Do not mix those tables. No new route-selection images are generated.

- Save weights every 2k; stride4 validation at 2k,4k,...,20k, same frames both arms.
- Select minimum ssi AbsRel; exact ties choose the earlier checkpoint.
- Always report fixed20k full validation separately from selected-checkpoint full
  validation. Never use one arm's fixed-step score against the other's selected score.
- Final `summary.json` includes curve, fixed20000, selected_step and selected_full.
- No test jobs or automatic claim of a caption benefit. A tiny gain is reportable
  as a point estimate, not proof of statistical robustness or all-metric superiority.

## Jobs / output isolation

Base: `$IRIS_RUNS/outputs/lotus_line_v2/sd21_tadp_pair_v1`.
Default data/manifests: `/mnt/scratch/dwdh0363/from_sc23sz` as in current DA2 jobs.
All HF loads are offline; GPU jobs will not download or install dependencies.

After syncing the six new files to Aire, submit once from a login node:

```bash
cd ~/Iris && bash slurm/submit_sd21_tadp_pair.sh
```

This submits:

1. `sd21_td_smoke`: CPU unit tests then 32 updates per arm, frozen parameter checks,
   nonzero text cross-attention gradient, U-Net/head changes, eight-frame validation,
   paired initialization/contract/image-order verification.
2. `sd21_td_frame`: `afterok:<smoke>`, 20k train + curve + full validation.
3. `sd21_td_empty`: same dependency and budget, independent output directory.

Both training jobs use `--kill-on-invalid-dep=yes`. Smoke failure cannot release
training. Contract mismatch after a code/config edit also prevents training. Fresh
submission refuses existing formal arm directories. Smoke uses separate outputs
and is never resumed into formal training. Do not resubmit the whole chain twice.

CPU tests require the existing iris torch/diffusers/transformers environment.
No ambiguous `from tests...` imports and no extra TADP/mmcv environment required.

Inspect the smoke (replace JOBID):

```bash
grep -E '^\[(thermal|train|val-result|paired-smoke|completed)\]' ~/Iris/sd21_td_smoke-JOBID.out
tail -n 30 ~/Iris/sd21_td_smoke-JOBID.err
```

If a formal job hits its 48-hour wall limit, resume ONLY that arm with the original
successful smoke directory; no other job may be writing that arm:

```bash
cd ~/Iris
export SMOKE_OUTPUT=/mnt/scratch/dwdh0363/runs/outputs/lotus_line_v2/sd21_tadp_pair_v1/smoke_JOBID
sbatch -J sd21_td_frame --export=ALL,ACTION=train,ARM=frame,RESUME=1 slurm/sd21_tadp_pair.sbatch
# Replace ARM=frame / job name by empty only if resuming the empty arm.
```

Milestone files contain U-Net/head weights only; `last.pt` includes optimizer/RNG.
There are ten milestone files per arm, plus one rolling full checkpoint. Budget
roughly 100-130 GB total including temporary checkpoint writes; do not save all
pixelwise predictions by default. Exact runtime depends on Aire hardware; use the
smoke's measured seconds/update, not DA2's timing. The 48-hour request is a limit,
not a measured runtime estimate.
