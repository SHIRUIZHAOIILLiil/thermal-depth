## E. 要你定的三件

1. **`nocap` / `rgbcap` 要不要也做度量适配？**
   交接文档里记着"三条臂都要适配"，那是**八页 3DV 时代**定的。现在四页、主干是
   caption，我倾向**不做**：消融留在相对深度口径，一句话声明度量适配是为进基线
   表的部署步骤。省两次适配训练 + 评估。

2. **1 参数 vs 2 参数的对照要不要测？**
   `--metric-source raw_inverse --align-mode median` 就能让我们走基线一模一样的
   1 参数协议。**预期落在 0.10–0.16**（依据：全局仿射 0.1207/0.1204/0.1516，
   完全不拟合 0.67）。测出来能把"我们多一个自由度"从含糊免责变成有量的披露。
   **重要但不紧急**，建议等主表定了再说。若之前评估开过 `--save-raw-pred`
   则完全免费，查：
   ```
   grep -l '"raw_predictions_saved": true' $IRIS_RUNS/eval/*/eval_eval.json | head
   ```

3. **主表要不要两个对齐口径都放？**
   我的建议是放，加一列注明口径。`align=none` 那一列是**回应"多一个自由度"质疑的
   唯一办法**——那一列谁都不拟合，零自由度对零自由度。
