# 我们的线与 Iris Lotus-G 线的完整差异（2026-09-01 审计）

一句话：**我们跑的就是 Iris 的 Lotus-G 线，只换了三处输入。**本文列出全部差异，
每一处标明是"必须换"还是"多出来的"，以及多出来的那些怎么处理。

审计方法：逐 flag 比对两个启动脚本，逐行比对两个训练器的掩码与损失段落，逐函数
比对两个数据集的掩码定义。不是凭印象。

---

## 一、配方：逐项相同，一处不差

`train_iris_g_depth.sh` vs `train_iris_ms2_g_depth.sh`：

| | Iris | 我们 |
|---|---|---|
| `norm_type` | `trunc_disparity` | `trunc_disparity` |
| batch × 梯度累积 | 4 × 3 = 12 | 4 × 3 = 12 |
| `max_train_steps` | 20000 | 20000 |
| `seed` | 42 | 42 |
| `learning_rate` | 3e-05 | 3e-05 |
| `lr_scheduler` / warmup | constant / 0 | constant / 0 |
| `timestep` | 999 | 999 |
| `max_grad_norm` | 1 | 1 |
| 存点间隔 | 1000 | 1000 |
| `use_8bit_adam` / `gradient_checkpointing` / `random_flip` | 开 | 开 |

我们把其中八个做成了环境变量（`${SEED:-42}` 这种写法），**默认值与 Iris 逐一相同**，
不设就是原值。

损失也相同。掩码构造段落（8×8 池化、天空加回、无掩码退化全 1）与
`train_iris_g.py:1048-1057` **逐字相同**；损失式 `MSE_{M_z}(ẑ,z) + MSE(ẑ_I,z_I)`
与 `:1151-1153` 相同。

---

## 二、必须换的三处：输入

Iris 用 **RGB + caption + 稠密渲染 GT**，我们用 **热像 + caption + 补全伪 GT**。

| # | 换了什么 | 为什么非换不可 |
|---|---|---|
| 1 | RGB → 热像 | 这是本工作的问题本身 |
| 2 | 数据集自带 caption → InternVL3-8B 从**热像**生成 | MS2 不带 caption，且 caption 必须来自热像，否则等于用了第二个相机 |
| 3 | 渲染稠密深度 → 补全伪深度 | MS2 只有稀疏 LiDAR。latent 目标要过 VAE 编码器，稀疏图编码不出有意义的 latent |

第 3 处的连带后果：`M_z` 的来源从"渲染深度的量程检查"变成"补全图的量程检查"。
**机制不变，输入变了**——两边都是"稠密图落在 `[d_min, d_max]` 内"，两边都不是
传感器命中图案。

## 三、多出来的差异：四条，逐条交代

### ⚠️ 1. 真实 LiDAR 盖到伪深度上（第四个变量）

`ms2_thermal_dataset.py` 曾无条件执行 `dense = clip(where(real, gt, pseudo))`：
补全图里 **26% 的像素被换成真实测量**。

Iris 没有对应物——他们的目标是一整张渲染图，处处连续。这让我们的 latent 目标
成了"平滑的伪深度 + 盖上去的测量值"的混合体，而**覆写处与伪深度平均差 6.2%**
（`tools/audit_pseudo_by_depth.py`，300 帧），也就是说目标里有真实的不连续。

**处理：`--pure_pseudo_target` 关掉覆写。**开了之后 latent 目标 100% 是伪深度，
与 Iris 的"一张连续稠密图"结构一致，第四个变量消失。

### 2. `_get_valid_mask` 的 `>` 改成 `>=`

VKITTI 写 `depth > d_min`，我们写 `depth >= d_min`。原因写在代码注释里：补全图被
clip 进 `[d_min, d_max]`，像素会正好落在 `d_min` 上；严格 `>` 会让它既不属于有效
掩码也不属于天空掩码，而 8×8 池化会因此作废整个 latent cell——64 个监督像素赔 1 个。
VKITTI 的深度是渲染的，不会落在边界上，所以那里没有这个问题。

**处理：保留，理由已在注释里。**

### 3. `d_min` 从 1e-5 改成 1e-3

⚠️ **这一处没有记录理由。**实际无影响：MS2 是米制，没有真实深度落在 0.01 毫米到
1 毫米之间，两个阈值筛掉的是同一批像素（非有限值和零）。

**处理：补一行注释说明它无影响，或改回 1e-5 以求完全一致。**

### 4. `--no_captions`

Iris 的脚本没有无 caption 臂。我们需要它，因为"caption 起不起作用"就是本工作要
回答的问题，而回答它需要一个对照臂。

**处理：保留。这是本工作的实验设计，不是对配方的改动。**

## 四、要从故事里去掉的

以下开关是为已放弃的路线加的，默认关或默认与原版一致，不影响 Lotus-G/D：

- `--backbone`（marigold / e2eft）
- `--prediction_type`（v_prediction）
- `--lr_total_iter_length`（那两条底座的指数衰减调度）
- `--sky_mask_dir`（天空实验，不设即关）
- `--lambda_image` / `--pure_pseudo_target` 之外的 lambda（默认值即原始目标）

**它们的存在不改变 Lotus-G/D 的行为**，但会让流程图和叙述显得杂乱。汇报时不提，
论文里不写。

## 五、三条路，按顺序走

| | 内容 | 状态 |
|---|---|---|
| **路 1 · baseline** | 只用真实稀疏 LiDAR 训 U-Net，图像空间掩码 SSI-L1，无 teacher | 训练中 |
| **路 2 · Iris 线换输入** | 热像 + caption + **纯**伪 GT，其余与 Iris 逐项相同 | 需要开 `--pure_pseudo_target` |
| **路 3 · 只在路 2 仍不够时** | 在路 2 之上，把 latent 解码成图，在**米空间**对真实回波加一项 L1 | 代码就位，未投 |

路 3 是**加法**，不是替换：它不动路 2 的任何东西，只多一个默认为零的项。这样三条
路互相之间只差一个变量，任何两条都可以直接比。
