### 我们的适配线

**路径**：`tools/finetune_depth_anything_thermal.py`

他们的仓库只放出**米制**变体的微调代码（SiLog），而米制是仿射不变表里的错目标，
所以配方是我们自己写的。数据这一侧和我方那条线**逐项相同**：

- 官方 8 序列划分
- 补全伪深度 + 真实激光覆写(同一份目标)
- 同一条 val 选点规则

⛔ **2026-09-29 修正：第一版（v1）的目标函数和训练过程都不是 DA2 的。**

v1 训的是**我方**那条线的损失和流程。逐项对过 DA2 论文、DAv1 论文（DA2 沿用它的
损失）和他们开源的 `metric_depth/` 代码之后，**共 7 处不一致**：

| # | DA2 的配方 | 出处 | v1 |
|---|---|---|---|
| 1 | $L_{ssi}$ 用**中位数 / 平均绝对偏差**归一化：$t=\mathrm{median}(d)$，$s=\frac1{HW}\sum|d-t|$ | DAv1 公式 | 最小二乘拟合 |
| 2 | $L_{gm}$ 算在**归一化后的残差**上，4 个尺度 | MiDaS（DA2 引用） | 无 |
| 3 | $L_{ssi}:L_{gm}=$ **1:2** | DA2 原文 | 只有 SSI |
| 4 | 伪标签样本**忽略损失最大的 10%** | DA2 原文 | 无 |
| 5 | 短边缩到 518（图像三次、深度最近邻、14 的倍数、lower bound）+ **随机裁 518×518** | `dataset/transform.py` | 整帧 |
| 6 | **随机水平翻转** | `train.py` | 无 |
| 7 | **poly 衰减** $(1-\mathrm{it}/\mathrm{total})^{0.9}$，**不裁梯度** | `train.py` | 常数学习率，裁到 1.0 |

一致的：AdamW（论文写 Adam，代码是 AdamW，以代码为准）、wd 0.01、编码器 5e-6 /
解码器 ×10、fp32、推理走整帧 + `DPTImageProcessor`（训练裁块、推理整帧是他们自己的约定）。

**有意不照搬、只披露**：batch 与步数（他们学生模型 192 × 480K，单卡对不齐）；DAv1 在
无标签流上的强颜色扰动和 CutMix（DA2 没说保留）；他们「天空设为视差 0」的规则 ——
那属于**目标怎么造**，而目标是所有臂共用的那一侧。

现在脚本的**默认值就是 DA2 的配方**，每项出处写在文件头；`LEGACY=1` 逐位复现 v1，
留作消融。作业：`slurm/da2_train.sbatch`。本地验证：v1 损失逐位复现、median/MAD 版
仿射不变（差 3e-8）、256×640 缩放为 518×1288 与他们的 `np.round` 取偶一致、图像与
目标同框同翻转。

⚠️ **别把这次修正说成「偏向谁」**。方向是双向的：v1 让它的训练目标和被报告的度量
（最小二乘对齐后的 AbsRel）对齐（帮它），同时拿掉了它自己的 GM、裁块和调度（害它）。
净效应未知 —— 这正是要重跑而不是估算的理由。

⭐ **编码器不冻结。** 他们自己的米制配方就是用解码器十分之一的学习率微调编码器；
冻住它等于让一个 RGB 预训练的编码器盯着热像看 —— 赢一个被绑住一只手的对手证明不了
任何事。编码器 `5e-6`，解码器 `5e-5`，20000 步，batch 4。

**门禁**：第 0 步的 AbsRel 必须落在 `[0.08, 0.30]`。它挡下过两个 bug ——
没走 `DPTImageProcessor`，以及诊断参照拿了补全伪深度而不是激光。

⚠️ 每 2000 步 `save_pretrained`，但**没有 resume 逻辑**。被时限杀掉的话
checkpoint 都在，接不上，只能重来或者用手上最好的那个。

## 二、Pixel-Perfect Depth

| | |
|---|---|
| 出处 | NeurIPS 2025 |
| 参数 | 约 **500 M** |
| 结构 | **像素空间扩散，没有 VAE** —— DiT，depth 24、hidden 1024、patch 8（有效 16） |
| 训练目标 | **log 深度，2%/98% 分位** |
| 原生输出 | ✅ **实测是 log 深度**（2026-09-24，作业 7941688，官方 train 划分 50 帧） |
| 评估对齐 | ✅ **`ssi_log`** —— 和我们自己这条线同一个对齐族 |

### ⭐ 为什么它不只是一个对比对象

**1. 它就是「去掉 VAE」的那条路。** 我们现在的瓶颈测量全在输出侧的 VAE 往返上；
PPD 在像素空间直接扩散，根本没有这个环节。它的成绩是那条路值不值得走的现成证据 ——
**比我们自己动手换解码器便宜得多**。

**2. 它的目标就是我们刚换上的那个。** log 深度 2%/98% 分位。这是当初指向 log 的
三条独立证据之一(另外两条是我们自己的 VAE 往返实测，和 Marigold V2 的默认选择)。

⭐ **而且实测证实了这一点**：`--probe-output-space` 在官方 train 划分上判定它的原始
输出仿射于 **log 深度**空间。所以两边用同一个 `ssi_log` 对齐，**不存在跨族打分的
问题** —— 这在这个项目里是难得的干净对比（跨族实测能差 30 倍）。

### 训练与评估的验证（2026-09-24）

| | |
|---|---|
| 训练 | 作业 7938012，4:46:33，25 个 checkpoint（e000–e024，共 50,000 步） |
| 起步权重 | ✅ `Loading ckpt: e000-s000000.ckpt`，`Trainable params: 499 M` |
| 评估侧加载 | ✅ `dit 352/352`，`sem_encoder 0/343`（后者由 `semantics_pth` 提供，本就不该来自 checkpoint） |

⚠️ **预算不对等，必须披露：PPD 拿了 4.8 GPU-小时，我方 log 线是 12.6。**
而且配置里有 `limit_train_batches: 2000`，所以「25 epoch」实际是对 75,688 帧数据的
**约 2.6 遍**（每 epoch 只看 8,000 帧，但逐 epoch 重新洗牌，覆盖是全的）。

⛔ **他们自己的推理入口也有静默失败**：`run.py:36` 是
`model.load_state_dict(torch.load(model_pth), strict=False)`，连 `sem_encoder` 的
加载也是 `strict=False`。一个键都对不上也不报错。我方的加载器按子模块报匹配数并
对 `dit` 断言，**比他们自己的流程更安全** —— 这句可以写进论文的复现说明。

### 我们的集成

**路径**：`integrations/ppd/`

| 文件 | 干什么 |
|---|---|
| `ms2_thermal.py` | 数据集，拷进克隆树当 `ppd/data/ms2_thermal.py` |
| `prepare_ms2.py` | 造 split JSON + 转 checkpoint |
| `train_ms2_thermal.yaml` | 训练配置，batch 4，AdamW `1e-4` |

放在我们仓库而不是他们的:改了什么留在自己的审查下,而且他们的克隆树永远是没被我们
编辑过的。

数据集只覆写三个方法(其余基类已经做了):

- `read_rgb` —— 他们读 8 位彩色除以 255;我们是 16 位单通道热像,拉伸到 8 位用
  **1%/99% 裁剪**(min-max 会让中位帧损失 14.3 点的相邻差分辨率),和我们自己那条线一致
- `read_depth` —— 补全伪深度 + 激光覆写,同一份目标
- `build_metas` —— 从我们的 manifest 生成他们那种两条并行路径列表

### ⛔ 2026-09-29 逐项核对：v1 的分辨率错了

对照 PPD 论文、他们的 `train_finetune.yaml`、数据集基类、`ppd_train.py`、
`transform.py`、`ppd.py`、README 逐项核过。**他们的训练代码我们一行没改**，所以
目标函数本来就是他们的：

| 项 | 他们 | v1 | |

| 损失 | 速度 MSE（带掩码）+ `multi_scale_grad_loss` ×0.2，仅在 `pretrain: False` 时开 | 同（我们配置 `pretrain: False`） | ✅ |
| 目标归一化 | log、2/98 分位（只在 `mask & depth<80` 上算）、clamp [-0.5, 1.0]，在他们管线里 | 同 | ✅ |
| 语义编码器 | 冻结 | 同 | ✅ |
| DiT / 调度 / 采样 / 时间步 | 24 层 1024 维 patch 8；lerp T=1000；euler v_lerp；logitnormal；推理 4 步 | 同 | ✅ |
| 优化器 | AdamW 1e-4，**wd 0.0**，bf16-mixed | 同 | ✅ |
| 增强 | 无 | 无 | ✅ |

⛔ **主问题在分辨率。** v1 在 163,840 像素上训、在 788,480 像素上评，**4.8 倍的训练/
测试面积差** —— 他们的配方训练和推理是同一个面积，这个错位是我们引入的。配置头里原来
那条「RoPE 让权重在任何分辨率都能跑，所以不 Resize 是安全的」对，但答非所问：能跑不等于
和他们的配方一样。PPD 适配后只有 9.52、val 在 e014 之后翻头，这**可能**是原因之一 ——
不能断言，但不能不修。

两处小错位（量化、掩码）顺手对齐：训练端 `read_rgb` 现在和推理端 `thermal_to_rgb` 在真实
MS2 帧上**逐位相同**（本地验证，差 0）。

⚠️ 零样本那一行**不受影响**：没有训练，推理本来就是他们的约定。

**v2**：配置里加回他们的 `Resize(1024, 768)`，其余不变，同样 25 epoch × 2000 批。像素多
4.8 倍，v1 的 4:46 预计变成一天上下 —— 先冒烟量速度和显存。显存不够用 `BS=2 ACCUM=2`，
有效 batch 仍是 4。⚠️ v1→v2 **动了三处**（分辨率，外加量化和掩码两处小的），所以两者
之差读作「他们的配方 vs 偏离了的配方」，**不能**当成纯粹的分辨率效应引用。

**只披露、不照搬**：他们是 8 卡 × batch 4 × 500 epoch（单卡对不齐）；他们微调配置里的
MoGe2 语义编码器对应的是另一份 checkpoint。

### ⭐ 主表各报哪一版：每条基线报更强的那个

| 基线 | 报 | 理由 |
|---|---|---|
| DA2 | **v1**（我方损失，day 0.08195） | 按它发表的相对深度配方（v2）在我方目标和预算下反而差（0.110） |
| PPD | **v2**（它自己的配方） | v1 的问题是我们引入的分辨率 bug，修掉后九格全好 |

原则：对比基线时给它最好的配置，而不是对我们最有利的那个。两版都试过、报更强的，
审稿人就无法说我们削弱了对手。两版都要在正文或补充材料里出现。

### ⚠️ 已经踩掉的一个静默坑

他们仓库里**两个加载器互相打架**:

```
load_pretrained_model        torch.load(path)["state_dict"]              训练用
load_pretrained_model_eval   torch.load(path)，dit.* -> pipeline.dit.*   推理用
```

发布的 `ppd.pth` 是第二种形式,而训练走 `find_last_ckpt_path`,它**只 glob `*.ckpt`**
然后直接索引 `["state_dict"]`。所以拿已发布权重微调会从三个方向失败 —— 扩展名不对、
键不存在、名字没前缀 —— **而且找不到就静默从随机初始化开始训**,没有任何报错。

`prepare_ms2.py` 照搬他们 eval 加载器的重映射,再包一层训练加载器要的外壳。

### 选点规则（2026-09-24 定，**在 val 曲线出来之前**）

⭐ **val AbsRel 最低；并列时取更早的那一步。** 与 DA2 同一条规则。

「并列」的判据由 `summarize_checkpoint_sweep.py` 给：最优与次优之差小于相邻点跳动
的中位数，就算并列。这条判据也和 DA2 那次同一套。

扫描范围：25 个 checkpoint 里每 5 个 epoch 取一个 —— `e004 e009 e014 e019 e024`
（`PATTERN="e0[0-9]*[49]-s*"`）。⚠️ 不是全部 25 个：PPD 每帧要跑 500M 的 DiT 四步
采样，25 × 14,249 帧约 49 小时、逐帧 `.npy` 约 233 GB。先用 5 个点 × 2,000 帧看形状。

⚠️ **如果工具报「分不出名次」**，按上面的规则取更早那一步，并在表注里写明
「val 在此采样量下分辨不出，按事先约定取更早的一步」。**不允许**因为分不出就去
跑多个点的 test 再挑 —— 那是拿 test 选点。

## 二点五、AnyThermal 放在哪(2026-09-21 补)

**和 DA2 同族**:前馈判别式 + 相对深度(MiDaS 系),按 `ssi` 对齐,不是扩散模型。
但 **AnyThermal 是热像原生的,DA2 没见过热像** —— 所以这一族里 AnyThermal 是硬
对手,DA2 零样本是弱的,那条适配线存在的理由就是把弱的换成硬的。

数已经齐了(官方子集,三条件三指标):AbsRel 0.0810 / 0.0872 / 0.1020,
RMSE 2.614 / 2.514 / 3.159,δ1 0.9424 / 0.9380 / 0.9048。**不用再跑。**

⚠️ **但它生成我们的训练目标**(`build_anythermal_pseudo_gt.py`:它的预测逐帧对
激光标定,再当作另一个 GT 来源)。赢它说明的是**激光覆写加训练补进了它没有的
东西**,不说明架构更好。⭐ **这一句必须进表注**,审稿人翻到伪 GT 来源就会问。
措辞按项目规矩走「监督部分来自 AnyThermal 的预测」,禁用 teacher / distill。

✅ **已核(2026-09-21):不是零样本。** AnyThermal 的深度监督就是
**MS2 自己的 train split + 稀疏 LiDAR GT**,和我方同源(`AIRE_RESULTS_20260802.md`
§复现验证,出处是它论文 §III-B / §III-F / §VI-C:"depth baselines are trained on
the evaluation datasets")。复现核对:它 Table IV 报 0.0883 / 2.7432(三条件平均),
我方重跑 0.0821(仅 day),量级吻合。

⛔ **坑**:它 §III-B 有一句 "MS² reserved for zero-shot evaluation" —— **那句只管
VPR,不管深度**。只看那句会把它误判成零样本。

⭐ 所以这个对比**在数据上是公平的**,和 DA2 零样本不是一回事,赢它有含义。剩下的
差异要进表注:骨干 DINOv2 ViT-B/14 vs SD U-Net;深度头 MiDaS vs 扩散单步 x0;
**训练时骨干冻结只训头 vs 整个 U-Net 解冻**。最后一条可能不只是差异而是解释 ——
稀疏激光在远端与天空无信号,全解冻的 U-Net 在无监督区漂移,冻结骨干保住了 DINOv2
的语义先验,这对得上我方 RMSE 全输而 AbsRel/δ1 全赢的形状。
